# Native dimension lighting candidate

October 2, 2026. Experimental, opt-in Rift Traveler test build; not a stable
external API or release. Official Manifold and Chart are untouched.

`DimensionLightCompatibility` binds an existing world provider and Manifold
numeric dimension ID. It contains no FD code, terrain height, extra illuminator,
source cache, lighting repair timer, or chunk-resend loop. Multiple providers
(including client and server in singleplayer) share patch ownership safely;
disposing one binding cannot unpatch another. Only the consumer ModSystem knows
the Fractured Deep code. Other developers should not use this internal API yet.

## What changes

- A thread-local propagation scope normalizes malformed encoded-Y block-entity
  lookups only in the propagator's own accessor and opted-in world/dimension.
  Caller-owned positions are never edited. Finalizers restore nested scope.
- Server light-removal packet 72 receives InternalY rather than local Y, only
  when sent by the matching world inside the original removal call. Ordinary
  packet storage, HSV and the client handler are unchanged.
- The server's normal block-light update is queued when its target dimension
  chunk is loaded but the unrelated overworld map chunk is absent. The existing
  dispatcher stays authoritative when that map chunk is present. No unloaded
  terrain is loaded or generated by this fallback.

The module validates the installed 1.22.7 engine signatures before installing
patches. A failure removes its partial patches and logs an error. Server startup
then retains the legacy adapter. When initialization succeeds, the legacy
`FracturedDeepBlockLightAdapter` starts no illuminator, listeners or notifications.
The client periodically checks Manifold metadata for FD's numeric ID; this is a
binding refresh, not a lighting scan. Leave-world/disposal removes its binding.

## Enable and rollback

Use `ModConfig/RiftTraveler.DimensionLighting.json` on both client and server:

```json
{
  "Enabled": true,
  "CorrectInventoryLookups": true,
  "CorrectRemovalPackets": true,
  "CorrectMissingMapDispatch": true
}
```

All switches require a full client/server restart. Missing config defaults to
`Enabled: false`; ordinary released behavior is not switched automatically.
Partial correction settings are diagnostic controls, not recommended working
combinations. Client config is local; it is not synchronized from the server.

Set `Enabled` to `false` and restart to restore the legacy repair writer. No
dimension IDs, blocks, inventories or saved item attributes are migrated.
For binary rollback, the previous installed DLL is backed up at
`backups/native-light-candidate-2026-10-02/RiftTraveler.previous.dll`.
Do not run both repair writers together. Do not purge the dimension to test this.

Expected server startup log: native dimension lighting active, followed by
legacy block-light repair disabled. Client logs its native binding after the
Manifold mirror supplies the dimension. Missing either log merits investigation.

## Verification and remaining limits

The Atlas server-queue, native client-buffer, packet and second-dimension disk
reload scenarios now exercise the actual runtime module. The startup scenario
seeds enabled config and verifies the old writer is absent, native small-lantern
placement/removal works, and ordinary seamstone placement/removal lights normally.
Other tests retain disabled config to cover the legacy path and known baselines.
All 19 Atlas scenarios passed on October 2, 2026. The candidate was then installed
and enabled only in the local `VintagestoryData-Test` folder; release ZIPs and the
live server were not updated.

The candidate does not handle absorption-only dispatch, arbitrary malformed
engine positions, natural distance-based server eviction, multiplayer timing or
all generation-time source initialization. It does not retroactively relight
old saved terrain. FD's existing one-time Threshold relight remains unchanged;
it is separate from the disabled periodic repair writer. In-game testing must
include generated seamstone and distant newly generated terrain, not just placed
sources. No claim is made yet that visual flashes are eliminated.

Test in FD: small floor lantern placement, pickup/break, lining bonuses,
overlapping torch, torches and large lanterns, placed/generated seamstone, travel
out/back, save/reopen, and previously unseen chunks. Check for instant normal
updates, repeated flashes, residual light or sources going dark. Repeat basic
lantern/torch controls in the overworld. Report failures with `/rt debug lightinfo`
while targeting the affected source and the client/server logs.
